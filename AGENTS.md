# Agent operating rules

## Authority

Repository documentation and current code are the source of truth. Issue #1 is the foundation mission; Issues #2-#10 are the approved roadmap. Preserve unrelated work and use one implementation owner for overlapping files.

## Roles

- Atlas: scope, orchestration, synthesis, and founder escalation.
- North: strategy, sequencing, operating model, and dependencies.
- Scout: research, platform constraints, licensing evidence, and source verification.
- Forge: implementation owner for repository and code changes.
- Bolt: validation, automation, performance, and delivery checks.
- Sentinel: independent acceptance, privacy, security, and launch-gate review.
- Signal: brand, character, voice, merchandise, and content consistency.

## Workflow

- Read the active issue and every dependency before planning.
- Work on `codex/` branches; keep changes focused and reversible.
- Do not claim downstream production work complete when only its foundation is documented.
- Every meaningful implementation slice requires independent Sentinel review.
- Run relevant checks and document assumptions, evidence, and unresolved gaps.
- Update the decision log for durable choices.

## Hard stops

Founder approval is required before public deployment or publication, purchases, legal commitments, production orders, account or credential changes, collection of submissions, external messages, or merging. Never build custom payment processing. Never expose private alliance information or use protected Kingshot/CenturyGames logos, screenshots, interfaces, characters, or other copied assets.
